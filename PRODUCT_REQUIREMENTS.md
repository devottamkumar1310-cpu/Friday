## 1. Scope Model

Requirements are tagged with a release tier. Nothing outside **M0/M1** may be built before those ship.

| Tier   | Meaning                                                              |
| ------ | -------------------------------------------------------------------- |
| **M0** | Shipathon MVP — the demonstrable core loop. Must exist.              |
| **M1** | Public Beta — makes the product usable daily by a stranger.          |
| **M2** | v1.0 — makes it defensible.                                          |
| **M3** | Post-v1 — explicitly deferred, documented so we stop re-debating it. |

Priority within a tier: **P0** = release blocker, **P1** = should ship, **P2** = if time permits.

## 3. Non-Functional Requirements

### NFR-1 · Performance

| ID      | Requirement                                     | Target                                               |
| ------- | ----------------------------------------------- | ---------------------------------------------------- |
| NFR-1.1 | Mission Control first contentful paint          | p95 < 1.2s                                           |
| NFR-1.2 | Mission Control fully interactive               | p95 < 2.0s                                           |
| NFR-1.3 | Read API latency (non-AI)                       | p95 < 200ms, p99 < 500ms                             |
| NFR-1.4 | Write API latency (non-AI)                      | p95 < 400ms                                          |
| NFR-1.5 | AI streaming — first token                      | p95 < 1.5s                                           |
| NFR-1.6 | Full plan generation (async, streamed progress) | p95 < 45s                                            |
| NFR-1.7 | Next Action computation                         | p95 < 300ms (deterministic — no LLM in the hot path) |
| NFR-1.8 | Nightly re-plan batch                           | 10k users in < 30 min                                |

> **NFR-1.7 is architecturally load-bearing.** The Next Action must be computed by the deterministic engine, with **no LLM involvement at all** — the rationale is rendered from a deterministic template over the live factor table ([AI_DECISION_ENGINE §12.2](AI_DECISION_ENGINE.md#122-the-generation-rule)). Storing pre-generated prose would let the explanation name a factor that no longer dominates.

## 4. MVP Scope (M0 — Shipathon)

### The one thing M0 must prove

> **A student states a goal and a deadline, and FRIDAY tells them exactly what to do today — then keeps telling them, correctly, as reality changes.**

### In scope for M0

**The Golden Path** (must work end to end, no gaps):

```
Sign up
  → State goal + deadline + weekly availability
    → Curriculum generated (preset or AI)
      → Plan generated with feasibility verdict
        → Mission Control shows ONE Next Action
          → Start Session → study → self-rate
            → Mastery + Memory State update
              → Return to Mission Control → the Next Action has CHANGED, correctly
                → Ask the Coach a question → it already knows everything above
```

**M0 feature list (nothing else):**

1. Auth: email/password + Google (FR-1.1), with DOB capture and the minor-consent gate (FR-1.6)
2. Onboarding (FR-1.2–1.5)
3. Goal creation (FR-2.1)
4. Curriculum: 2–3 exam presets + AI generation (FR-2.2, FR-2.3, FR-2.6)
5. Plan generation + feasibility + versioning (FR-3.1, 3.2, 3.3, 3.4, 3.5)
6. Next Action engine, time-aware (FR-4.1, 4.2, 4.3)
7. Session lifecycle + self-rating (FR-5.1, 5.2, 5.3)
8. Mastery + FSRS memory state + episodic log (FR-7.1, 7.2, 7.3)
9. Practice questions: generate + grade (FR-6.1, 6.2)
10. Progress, on-track status, weak concepts (FR-8.1, 8.2, 8.3)
11. Context-aware streaming Coach with read tools (FR-9.1, 9.2)
12. Mission Control (FR-11.1, 11.2, 11.3)

### Explicitly NOT in M0

Nightly auto re-plan (manual re-plan button only) · notifications of any kind · daily brief · insights · root-cause analysis · mock tests · curriculum editing · uploads · calendar sync · flashcards · billing · admin console · mobile app · social/collab · voice · charts beyond a single progress ring.

### M0 Definition of Done

- [ ] A stranger completes the Golden Path unaided in < 10 minutes
- [ ] The Next Action demonstrably changes after a Session, for a reason the user can read
- [ ] The feasibility verdict is arithmetically correct and reproducible by hand
- [ ] The Coach answers "what should I do this week and why?" citing real state
- [ ] Zero P0 bugs; no crash on the Golden Path across 20 consecutive runs
- [ ] Deployed to a public URL with seeded demo account
- [ ] 90-second demo recorded

## 5. Out of Scope

### Deferred (will build, not now)

Mobile apps · calendar/LMS integration · multi-goal arbitration · mock test engine · uploads & OCR · voice · offline mode · collaborative study · institutional dashboards · marketplace.

### Out of scope — permanently, by principle

| Not building                              | Why                                                                                    |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| A general-purpose chatbot                 | Undifferentiated. The Coach is scoped to learning and to _this_ learner.               |
| Content library / video hosting           | Content is commodity. Context is the moat.                                             |
| Homework/answer solving                   | Violates _"effort belongs to the student."_ Removes the learning it claims to support. |
| Streak-guilt and shame mechanics          | Violates _"adaptation without guilt."_ Primary cause of abandonment.                   |
| Social feeds and leaderboards             | Comparison harms the deadline-driven user we serve.                                    |
| Proctoring / surveillance                 | Adversarial to trust.                                                                  |
| Selling or model-training on learner data | Non-negotiable.                                                                        |

## 6. User Stories

### Epic A — Getting Started

- **A1.** As a JEE aspirant, I want to enter my exam and date and get a real plan in under five minutes, so I can start today instead of spending a weekend planning. _(AC: plan visible ≤60s after onboarding; covers the full syllabus; respects my stated availability.)_
- **A2.** As a self-learner with a vague goal, I want FRIDAY to turn "learn ML in 4 months" into a concrete syllabus, so I don't have to know the field to start studying it. _(AC: ≥5 units, ≥30 concepts, ordered by prerequisites, with time estimates.)_
- **A3.** As a student who already knows some material, I want to mark topics as known so I'm not scheduled to relearn them. _(AC: excluded from planning; feasibility recomputes; still eligible for revision if evidence later contradicts.)_

### Epic B — Daily Use

- **B1.** As a student opening the app, I want one clear instruction, so I start working within seconds. _(AC: single dominant Next Action; ≤8s to comprehension; alternates hidden.)_
- **B2.** As a student with 25 free minutes, I want a task that actually fits, so the time isn't wasted. _(AC: recommendation duration ≤ stated time; different from the 3-hour recommendation.)_
- **B3.** As a student who missed three days, I want the plan to just absorb it, so I return without dread. _(AC: re-plan succeeds; no guilt copy; feasibility updated honestly; scope-cut options if now infeasible.)_
- **B4.** As a student finishing a session, I want to record how it went in one tap, so logging never feels like work. _(AC: ≤2 taps; mastery and due dates update; effect visible immediately.)_

### Epic C — Understanding Myself

- **C1.** As a student, I want to know whether I'll finish before my exam, so I can act while I still can. _(AC: on-track verdict + projected date + the arithmetic behind it.)_
- **C2.** As a student, I want to see which topics are weakest and why, so I stop guessing. _(AC: ranked list; each backed by citable evidence events.)_
- **C3.** As a student, I want proof I'm improving, so I keep going. _(AC: mastery trend over time; not hours-studied.)_

### Epic D — Coaching

- **D1.** As a student, I want to ask a question without re-explaining who I am, so help is immediate. _(AC: no context-gathering questions; response cites my actual goal/plan/weak areas.)_
- **D2.** As a confused student, I want the coach to find the _root_ gap, so I fix the cause instead of the symptom. _(AC: traverses prerequisites; names a specific upstream concept.)_
- **D3.** As a student, I want to say "I can't do Tuesdays anymore" and have the plan change. _(AC: coach proposes a concrete change; user confirms; new plan version written with reason.)_

### Epic E — Trust

- **E1.** As a student, I want to see and correct what FRIDAY believes about me. _(AC: memory view; edit and delete; deletions honoured immediately.)_
- **E2.** As a student, I want to leave with my data. _(AC: complete JSON export.)_
- **E3.** As a student, I want to understand every recommendation. _(AC: "why this?" on every Next Action, in plain language.)_

## 7. Core Workflows

### W1 — Onboarding → First Plan

```
Sign up → verify → goal + date + type
  → availability grid + blocked times
  → curriculum: preset  ─────────────▶ instant
                AI-generated ────────▶ async job, streamed progress UI
  → prerequisite edges built + cycle check
  → Plan v1 generated (deterministic scheduler)
  → feasibility verdict
      ├── on_track / at_risk ──▶ Mission Control
      └── not_feasible ────────▶ remediation screen (extend | add hours | cut scope)
                                    → user chooses → Plan v2 → Mission Control
```

**Failure handling:** AI curriculum generation fails → offer preset or a minimal user-defined outline. Never dead-end.

### W2 — Daily Loop

```
Open Mission Control
  → GET /next-action?available_minutes=N   (deterministic, <300ms)
  → student accepts (or skips → reason recorded)
  → POST /sessions  (start)
  → work
  → POST /sessions/{id}/complete  { ratings[], note? }
      → emit EvidenceEvents
      → recompute Mastery(concept)
      → advance FSRS MemoryState → next due date
      → mark Task complete
      → invalidate NextAction cache
      → enqueue: reflection (async), plan-drift check (async)
  → return to Mission Control → new Next Action, with visible reason for the change
```

### W3 — Adaptive Re-plan

```
Trigger: nightly sweep | drift > threshold | availability change | coach action | manual
  → snapshot current state (mastery, memory states, completed work, remaining scope)
  → recompute remaining required minutes  (learn + practice + PROJECTED reviews)
  → recompute available minutes to deadline × reliability factor (learned adherence)
  → run scheduler → candidate Plan v(n+1)
  → diff vs. v(n) → materiality check
      ├── immaterial ──▶ discard, keep v(n)   (avoids thrash and plan churn anxiety)
      └── material ────▶ commit v(n+1) with reason + diff
  → if verdict crosses into not_feasible → raise Directive with options
```

### W4 — Practice & Grading

```
Select concept (or accept a practice Task)
  → look for cached questions matching {concept, difficulty, unseen by user}
      ├── enough ──▶ serve
      └── short ───▶ generate (LLM, schema-validated) → validate → cache → serve
  → answer
  → grade: MCQ deterministic | short-answer LLM + rubric (schema-validated)
  → EvidenceEvent per concept  (correctness, latency, difficulty, confidence)
  → Mastery + MemoryState update
  → misconception detected? → write LearnerFact → may trigger remediation Task
```

### W5 — Proactive Intervention _(M1)_

```
Event stream + nightly sweep
  → detectors: deadline_pressure | plan_drift | retention_cliff | inactivity | milestone
  → candidate Directive (severity, type, payload)
  → NUDGE POLICY GATE: quiet hours? daily cap? type cooldown? relevance ≥ threshold?
      ├── fail ──▶ drop (logged, counts toward suppression metrics)
      └── pass ──▶ render copy (LLM, from structured facts) → deliver (inbox/email)
  → record outcome (seen/acted/dismissed) → feed relevance threshold
```

### W6 — Coach Conversation

```
Message received
  → CONTEXT BUILDER assembles LearnerContextPacket (deterministic, token-budgeted):
      identity + goal + deadline + plan summary + top weak concepts
      + recent sessions + relevant LearnerFacts + semantic retrieval hits
  → model call with read tools [get_plan, get_mastery, get_weak_concepts, get_schedule]
    and, at M1, write tools [reschedule, mark_known, create_task, trigger_replan]
  → write tools require explicit user confirmation in-UI before execution
  → stream response
  → persist turn; enqueue reflection → LearnerFacts
```

## 8. Success Metrics

### North Star

**Weekly Directed Study Minutes** — minutes studied inside sessions that originated from a FRIDAY recommendation. It captures engagement _and_ trust _and_ the core value proposition in one number. Raw study minutes would reward a dumb timer; this only goes up if the recommendations are good enough to follow.

### Activation & Retention

| Metric                                                           | M0 (demo) | M1 target       |
| ---------------------------------------------------------------- | --------- | --------------- |
| Onboarding completion                                            | ≥80%      | ≥85%            |
| Activation (plan created **and** first session completed in 24h) | ≥50%      | ≥60%            |
| D1 / D7 / D30 retention                                          | —         | 55% / 40% / 25% |
| W12 retention                                                    | —         | ≥20%            |
